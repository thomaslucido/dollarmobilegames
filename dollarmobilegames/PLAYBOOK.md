# Dollar Arcade Playbook

Every agent working in this repo reads this file first. It is the standing rulebook for the
twice-weekly build and the store deploys.

## What this is

One iOS app, **Dollar Arcade** (working name; bundle id `com.thomaslucido.dollararcade`).
The app is free to download and holds a shelf of small, original, polished games. The first
game is free; every other game is a **$0.99 one-time unlock** (non-consumable in-app purchase).

New games are built on **Monday and Saturday evenings** by the "Games · Build night" scheduled
task and shipped to Apple on **Tuesday and Sunday at 7am ET** by `.github/workflows/deploy-ios.yml`.
The App Store top charts are snapshotted every evening by `.github/workflows/charts.yml` into
`data/trends/`.

## The originality rule (non-negotiable)

We follow **trends**, never **titles**. A trend is a genre, a mechanic, a control scheme, or a
session shape that is rising in the charts (for example "merge puzzles", "one-thumb idle
builders", "physics stackers"). Mechanics and genres are free for anyone to use. Specific games
are not.

Every game we ship must have:

1. **Its own name.** No word, pun, misspelling or sound-alike of any charting game's name. No
   names that would make a shopper think it is made by, or related to, another studio.
   `scripts/validate.mjs` blocks names that overlap with any title in `data/trends/`.
2. **Its own look.** Our own palette, shapes, characters and icon. Never imitate another game's
   characters, mascot, logo, icon, color scheme or screen layout. No third-party art, fonts that
   need a license, sounds or music. Everything is drawn in code (canvas/SVG/CSS) or generated by us.
3. **A twist.** A rule, theme or goal that makes it plainly a different game from whatever
   inspired the trend. Write the twist down in `DESIGN.md` before writing code.
4. **No brand references** in text, metadata or keywords (Apple guideline 2.3.7 and 4.1).

If an idea cannot pass these four checks, pick a different trend.

## Apple rules we design around

- **4.1 Copycats / 5.2 IP:** see the originality rule.
- **4.2 Minimum functionality:** every game needs a real loop: a goal, rising difficulty, a fail
  state, a score or progress that persists, and at least 3 minutes of interesting play.
- **4.3 Spam:** each game must feel distinct from the games already in the arcade. Read
  `www/games.json` and `data/ideas.json` and do not repeat a genre within the last 6 games.
- **3.1.1 In-app purchase:** unlocks go through Apple IAP only. No outside payment links.
- **Restore Purchases** must stay on the arcade home screen.
- **No data collection.** No analytics, ads, trackers, accounts or network calls. Games run fully
  offline. The privacy label is "Data Not Collected"; keep it true.
- **Age rating 4+:** no violence beyond cartoon bonking, no gambling mechanics, no loot boxes.

## Technical contract for a game

```
www/games/<slug>/
  index.html     the whole game (inline JS/CSS is fine; may also add local .js/.css files)
  DESIGN.md      trend, inspiration category, twist, controls, difficulty curve, art direction
  icon.svg       512x512 square tile art for the arcade shelf (our own art)
  review.png     1290x2796 screenshot for Apple's IAP review (generated by scripts/shoot.mjs)
```

- Load `../../shared/game-kit.js` and call `GameKit.init({ slug })`. It gives you the Back
  button, safe-area insets, best-score storage (`GameKit.best()` / `GameKit.saveBest(n)`),
  haptics (`GameKit.buzz()`), pause on background, and the canvas sizing helper.
- Expose `window.__game = { state: () => ({ mode, score }) }` where mode is one of
  `title | play | paused | over`. The playtest script drives the game through it.
- Portrait, touch first, one or two thumbs. Must also work with a mouse for the web build.
- Target 60fps on an iPhone 12. Use `requestAnimationFrame` and delta time.
- No external URLs of any kind (no CDNs, fonts, images, analytics). Validation fails on `http`.
- Keep the folder under 1.5 MB.
- Sound is optional and must be generated with WebAudio, muted by default until first tap.

## Registry entry (`www/games.json`)

```json
{
  "slug": "lantern-drift",
  "name": "Lantern Drift",
  "tagline": "Hold to rise. Let go to fall. Catch every firefly.",
  "genre": "one-touch flyer",
  "free": false,
  "productId": "com.thomaslucido.dollararcade.game.lantern_drift",
  "added": "2026-10-21",
  "accent": "#f2a65a"
}
```

`productId` is always `com.thomaslucido.dollararcade.game.` + slug with dashes turned to
underscores. Only the very first game has `"free": true`.

## Idea ledger (`data/ideas.json`)

Append one record per build night, shipped or not:
`{ "date", "trend", "evidence", "concept", "name", "slug", "status": "shipped|parked|rejected", "why" }`.
Never reuse a parked name for a different concept.

## Models and effort per role (build night)

| Role | Model | Effort | Job |
|---|---|---|---|
| Orchestrator | the task's own session | default | runs the night, owns git, writes the summary |
| Scout | haiku | low | reads `data/trends/` + light web search, writes `data/scout/<date>.md` |
| Designer | opus | high | picks the trend, writes `DESIGN.md`, name check |
| Builder | opus | high | builds the game to the contract |
| QA | sonnet | medium | runs validate + playtest, files bugs back to Builder (max 2 rounds) |

Role briefs live in `playbook/agents/`.

## Definition of done for a build night

- `node scripts/validate.mjs` passes.
- `node scripts/playtest.mjs <slug>` passes (no console errors, game reaches a fail state and a
  restart under simulated input, frame time ok).
- `www/games.json`, `data/ideas.json`, `data/scout/<date>.md` updated.
- `review.png` generated.
- One commit on `main`: `Build night <date>: <Game Name>`.

If QA still fails after 2 fix rounds: push the work to branch `wip/<slug>`, log it as `parked`
in `data/ideas.json` on `main`, and do NOT add it to `games.json`. Nothing half-built ships.
