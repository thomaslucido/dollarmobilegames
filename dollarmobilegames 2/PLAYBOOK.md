# Dollar Mobile Games Playbook

Every agent working in this repo reads this file first. It is the standing rulebook.

## What this is

A studio pipeline that ships **one original iPhone game a week, each as its own $0.99 app**.

| When (Detroit time) | What | Where |
|---|---|---|
| Every evening ~7:13pm | Snapshot Apple's top Games charts into `data/trends/` | `.github/workflows/charts.yml` |
| Mon + Sat ~7:40pm | Build night: scout, design, build and QA one new game | Claude scheduled task, `playbook/BUILD_NIGHT.md` |
| Sat, end of build night | Pick the week's best unshipped game into `data/ship-queue.json` | `playbook/agents/picker.md` |
| On every push to the queue | Register the bundle ID, open a GitHub issue with Tom's 5-minute checklist | `.github/workflows/prepare-app.yml` |
| Sun ~7:07am | Build, upload and submit the queued app to Apple at $0.99 | `.github/workflows/deploy-ios.yml` |

Games that are built but not picked stay in the pool (`www/games.json`, status `built`) and can be
picked in a later week. Every game is also playable on the web preview at
https://thomaslucido.github.io/dollarmobilegames/.

## The originality rule (non-negotiable)

We follow **trends**, never **titles**. A trend is a genre, a mechanic, a control scheme, or a
session shape that is rising in the charts (for example "merge puzzles", "one-thumb idle
builders", "physics stackers"). Mechanics and genres are free for anyone to use. Specific games
are not.

Every game must have:

1. **Its own name.** No word, pun, misspelling or sound-alike of any charting game's name, and
   nothing that suggests it comes from another studio. `scripts/validate.mjs` checks names
   against every title in `data/trends/`.
2. **Its own look.** Our own palette, shapes, characters and icon. Never imitate another game's
   characters, mascot, logo, icon, color scheme or screen layout. No third-party art, licensed
   fonts, sounds or music. Everything is drawn in code (canvas/SVG/CSS).
3. **A twist.** A rule, theme or goal that makes it plainly a different game from whatever
   inspired the trend, written down in `DESIGN.md` before any code.
4. **No brand references** in text, metadata or keywords.

## Apple rules we design around

- **4.1 Copycats / 5.2 IP:** see the originality rule.
- **4.2 Minimum functionality:** a real loop: a goal, rising difficulty, a fail state, a best
  score that persists, and at least 3 minutes of interesting play. A $0.99 app must feel worth it.
- **4.3 Spam:** every app comes from the same developer account, so every app must look and feel
  like its own product: its own art style, palette, typography treatment, sound and UI layout.
  Never reuse another of our games' look. No shared "series" branding. Do not repeat a genre
  within the last 6 games.
- **2.3.7 Metadata:** no prices, no other apps' names, no keyword stuffing in name, subtitle or
  keywords.
- **No data collection.** No analytics, ads, trackers, accounts or network calls. Games run fully
  offline. Privacy label: "Data Not Collected".
- **Age rating 4+:** cartoon bonking at most, no gambling mechanics, no loot boxes, no purchases
  inside the app.

## Technical contract for a game

```
www/games/<slug>/
  index.html     the whole game (may add local .js/.css files)
  DESIGN.md      trend + evidence, twist, controls, difficulty curve, art direction, review note
  store.json     App Store listing (see below)
  icon.svg       512x512 square art, our own, no text (becomes the app icon)
  app/icon.png   1024x1024 app icon, no transparency   (generated by scripts/shoot.mjs)
  app/splash.png 2732x2732 launch screen                (generated by scripts/shoot.mjs)
  store/01.png, 02.png, 03.png  1290x2796 screenshots   (generated by scripts/shoot.mjs)
```

- Load `../../shared/game-kit.js` and call `GameKit.init({ slug })`. It gives you the Back
  button (web preview only; hidden in the iPhone app), safe areas, best-score storage
  (`GameKit.best()` / `GameKit.saveBest(n)`), haptics (`GameKit.buzz()`), pause on background,
  `GameKit.fitCanvas()` and a tiny WebAudio blip synth (`GameKit.sound()`).
- Expose `window.__game = { state: () => ({ mode, score }) }` where mode is one of
  `title | play | paused | over`. The playtest and screenshot scripts drive the game through it.
  Also add `demo(on)`: an autopilot that plays well, so the App Store screenshots show real
  play with a score instead of an instant crash.
- Portrait, touch first, one or two thumbs, also works with a mouse.
- 60fps with `requestAnimationFrame` and delta time.
- No external URLs of any kind. Validation fails on `http` references and network APIs.
- Keep the game files under 1.5 MB (generated `app/` and `store/` images do not count).
- Sound is optional, WebAudio only, silent until the first tap.

### `store.json`

```json
{
  "appName": "Lantern Drift",
  "subtitle": "Keep the little flame alive",
  "description": "3 to 5 short paragraphs. What you do, what makes it different, why it is fun. End with: No ads. No tracking. No in-app purchases.",
  "keywords": "comma,separated,max,100,characters,no,brand,names",
  "promo": "one line, under 170 characters",
  "category": "GAMES_CASUAL",
  "reviewNote": "How to play in one or two sentences for Apple's reviewer."
}
```

`appName` max 30 characters, `subtitle` max 30, `keywords` max 100 characters total.
`category` is the secondary category under Games: one of GAMES_ACTION, GAMES_ADVENTURE,
GAMES_ARCADE, GAMES_BOARD, GAMES_CARD, GAMES_CASUAL, GAMES_FAMILY, GAMES_MUSIC, GAMES_PUZZLE,
GAMES_RACING, GAMES_ROLE_PLAYING, GAMES_SIMULATION, GAMES_SPORTS, GAMES_STRATEGY, GAMES_TRIVIA,
GAMES_WORD.

## Registry entry (`www/games.json`)

```json
{
  "slug": "lantern-drift",
  "name": "Lantern Drift",
  "tagline": "Hold to rise. Let go to fall. Catch every firefly.",
  "genre": "one-touch flyer",
  "bundleId": "com.thomaslucido.lanterndrift",
  "added": "2026-10-21",
  "accent": "#f2a65a",
  "status": "built"
}
```

`bundleId` is `com.thomaslucido.` + the slug with dashes removed. `status` is `built` when it
lands, `queued` once picked, `submitted` once sent to Apple (the deploy workflow sets that).

## Ledgers

- `data/ideas.json`: one record per build night, shipped or not:
  `{ "date", "trend", "evidence", "concept", "name", "slug", "status": "built|parked|rejected", "why" }`.
- `data/ship-queue.json`: `{ "queue": [ { "slug", "pickedOn", "why", "status": "queued|submitted" } ] }`.
  At most one `queued` entry at a time.
- `data/releases.json`: written only by the deploy workflow.

## Models and effort per role

| Role | Model | Effort | Job |
|---|---|---|---|
| Orchestrator | the task's own session | default | runs the night, owns git, writes the summary |
| Scout | haiku | low | reads `data/trends/` + light web search, writes `data/scout/<date>.md` |
| Designer | opus | high | picks the trend, writes `DESIGN.md`, `store.json`, `icon.svg` |
| Builder | opus | high | builds the game to the contract |
| QA | sonnet | medium | validate + playtest + screenshot review, bugs back to Builder (max 2 rounds) |
| Picker (Saturdays) | opus | medium | chooses the week's best unshipped game for Sunday |

Role briefs live in `playbook/agents/`.
